# ChatGPT-first whole-worker credential mediation

Checked 2026-09-21. Primary-source inspection only; no model calls, credential/config reads, installation, VM launch, or runtime experiment. Baselines: installed Pi 0.86.1 and Gondolin source commit `29fa74d802112f29c720990aced26165e0d57d84`. This supersedes the earlier recommendation to prove isolation with OpenCode Go first: the user reports Go exhausted and ChatGPT available.

## Finding

There is a feasible **native composition to validate**, without a new provider implementation or standalone credential proxy: run Pi inside Gondolin with a synthetic JWT-shaped placeholder; use Pi's existing Codex adapter and native provider configuration; refresh OAuth on the host using Pi's existing auth runtime; update Gondolin's native secret manager before forwarding requests. Force SSE initially. This is source-supported design inference, not verified integration.

## Exact contracts and pitfalls

**Pi requires a parseable token before networking.** `extractAccountId(token)` requires exactly three dot-separated segments, applies `JSON.parse(atob(parts[1]))`, and reads `payload["https://api.openai.com/auth"].chatgpt_account_id`. It does not verify a signature. `buildBaseCodexHeaders` overwrites `Authorization` with `Bearer ${token}` and `chatgpt-account-id` with that extracted claim. A generic opaque Gondolin placeholder fails. A random, unique JWT-shaped placeholder containing only the required account claim can pass this local parsing; do not copy a real token payload with other personal claims. Treat account ID as sensitive metadata, not an access credential. A placeholder account ID with host-side header rewriting is possible if metadata concealment becomes necessary, but adds coordination and is not needed to keep bearer/refresh credentials out of the guest. [Pi 0.86.1 Codex adapter](https://github.com/earendil-works/pi/blob/v0.86.1/packages/ai/src/api/openai-codex-responses.ts)

**An API-key runtime override alone is insufficient.** The built-in `openai-codex` provider exposes OAuth only. `composeApiKeyAuth` deliberately returns `undefined` when the base has no API-key handler, no explicit configured `apiKey` exists, and OAuth exists. `resolveProviderAuth` honors API-key overrides/stored keys only when the composed provider has an API-key handler. Thus do not assume `--api-key` or `ModelRuntime.setRuntimeApiKey(providerId, apiKey, options?): Promise<void>` alone establishes available auth. The native guest `models.json` provider overlay can explicitly set `openai-codex.apiKey` to a placeholder environment-variable reference, adding the ordinary built-in config resolver while inheriting the native model catalog and Codex adapter. Alternatively an SDK configuration overlay can supply the same explicit key setting. Guest auth storage must contain no real OAuth credentials. [Provider composer](https://github.com/earendil-works/pi/blob/v0.86.1/packages/coding-agent/src/core/provider-composer.ts), [auth resolver](https://github.com/earendil-works/pi/blob/v0.86.1/packages/ai/src/auth/resolve.ts), [native models configuration](https://github.com/earendil-works/pi/blob/v0.86.1/packages/coding-agent/docs/models.md)

The name `apiKey` here describes Pi's token-input interface. It does **not** switch to OpenAI Platform billing: the inherited provider remains `openai-codex`, with base URL `https://chatgpt.com/backend-api` and native `openai-codex-responses` adapter. Its resolved inference path is `/backend-api/codex/responses`. Do not replace it with the `openai` provider or a Platform API key. This endpoint distinction does not prove the account cannot consume purchased subscription credits. [Native provider](https://github.com/earendil-works/pi/blob/v0.86.1/packages/ai/src/providers/openai-codex.ts), [adapter URL resolution](https://github.com/earendil-works/pi/blob/v0.86.1/packages/ai/src/api/openai-codex-responses.ts)

**Gondolin supports custom placeholders and native rotation.** Its exact relevant types are `SecretDefinition = { hosts: string[]; value: string; placeholder?: string | (() => string) }`; `createHttpHooks(options: CreateHttpHooksOptions = {}): CreateHttpHooksResult`; the result includes `httpHooks`, `env`, `allowedHosts`, and `secretManager`. The manager exposes `updateSecret(name: string, options: { value?: string; hosts?: string[] }): void` and `deleteSecret(name: string): void`. There is **no asynchronous secret-value callback** in this source. The placeholder generator runs at construction, not per request. `updateSecret` changes the host value while retaining the guest placeholder. At this pinned revision the wrapper awaits the user `onRequest` callback and then applies substitutions; this enables host refresh followed by `updateSecret` before injection. Higher-level docs warn hooks may see real secrets, including redirected requests: never log raw hook requests. [Pinned hook implementation and exported types](https://github.com/earendil-works/gondolin/blob/29fa74d802112f29c720990aced26165e0d57d84/host/src/http/hooks.ts)

**Refresh remains native and host-owned.** `ModelRuntime.getAuth(providerId: string, overrides?: ModelRuntimeAuthOverrides): Promise<AuthResult | undefined>` accepts `minOAuthValidityMs?: number`; host OAuth resolution refreshes credentials when remaining validity is below at least five minutes, rechecks expiry under credential-store modification, persists rotation, and derives the access token. This is preferable to implementing refresh requests ourselves. Use one trusted host auth runtime/store shared by worker launchers or verify file-lock behavior across processes. The adapter must synchronize refreshed bearer plus account ID as one account selection, and stop on refresh failure/logout; never forward a stale credential by falling back silently. The native resolver has a 15-second refresh timeout and double-checked store locking, but our composition still needs concurrency testing. [ModelRuntime declarations/source](https://github.com/earendil-works/pi/blob/v0.86.1/packages/coding-agent/src/core/model-runtime.ts), [OAuth resolver](https://github.com/earendil-works/pi/blob/v0.86.1/packages/ai/src/auth/resolve.ts)

## Request policy and transport

Use explicit global `allowedHosts` and per-secret `hosts`; the former is allow-all if omitted. Add `isRequestAllowed` policy for exact HTTPS authority/port, POST method, and `/backend-api/codex/responses`, with no arbitrary ChatGPT paths or query strings. In the refresh hook, check that scope before performing credential work. Allowlisted dependency registries receive no provider credential. Disable query substitution, mapped TCP, SSH egress, and guest access to OAuth refresh endpoints. Reject inappropriate auth headers/placeholders on other headers or paths: native replacement otherwise applies to every request header containing the placeholder, not only Authorization. Include redirected requests and same-host alternate paths in future policy tests. These are policy recommendations using existing hooks, not guarantees supplied by a hostname-only allowlist. [Pinned hook implementation](https://github.com/earendil-works/gondolin/blob/29fa74d802112f29c720990aced26165e0d57d84/host/src/http/hooks.ts), [network contract](https://github.com/earendil-works/gondolin/blob/29fa74d802112f29c720990aced26165e0d57d84/docs/sdk-network.md)

Pi's Codex adapter defaults `options.transport` to `"auto"`, attempting WebSocket before eligible SSE fallback. Explicit `"sse"` bypasses that attempt. Native settings expose `transport` and `SettingsManager.setTransport(transport: TransportSetting): void`. Gondolin supports WebSocket HTTP/1.1 Upgrade, but only the handshake is hookable; frames then form an opaque tunnel. Prefer explicit SSE plus `VM.create({ allowWebSockets: false })` for the first integration: provider requests and refreshed auth remain mediated on each HTTP request. This does not assert WebSockets are incompatible; they require a separate policy/lifecycle evaluation. [Pi adapter](https://github.com/earendil-works/pi/blob/v0.86.1/packages/ai/src/api/openai-codex-responses.ts), [settings manager](https://github.com/earendil-works/pi/blob/v0.86.1/packages/coding-agent/src/core/settings-manager.ts), [Gondolin network contract](https://github.com/earendil-works/gondolin/blob/29fa74d802112f29c720990aced26165e0d57d84/docs/sdk-network.md)

## Required later proof

Before any real worker is accepted: validate synthetic token parsing and configured-provider availability without credentials; inspect mediated requests with fake secrets; prove restrictions for headers, paths, redirects and revoked secrets; prove streaming/cancellation through guest TLS/HTTP; test refresh/logout/account-switch synchronization with two workers; then separately authorize an authenticated subscription check. No real access or refresh token may enter guest env, files, argv, logs, snapshots, or responses. An allowed upstream can reflect injected credentials, so narrow endpoint trust and tests remain necessary. If this native composition fails, record the concrete failing contract before considering a bespoke auth service.
